# 소개 사이트 (`site/`)

PyQuests 앱과 **분리된 정적 소개 사이트**입니다. 앱이 무엇인지 설명하는 화면이 없어서, 처음 방문한 사람이 대시보드의 "안녕하세요, 러너님!" · 진척도 0% · 잠긴 뱃지 · 모르는 사람들의 랭킹을 먼저 보게 되는 문제를 해결합니다.

```bash
npm run build:site     # site/index.html 생성
npm run check:site     # 최신 상태인지 확인 (CI 에서 실행)
```

---

## 1. 구조

| 파일 | 내용 |
|---|---|
| `site/index.template.html` | **편집하는 파일.** `{{...}}` 자리표시자가 들어 있습니다 |
| `site/index.html` | **생성물.** 직접 고치지 마세요 — `check:site` 가 잡습니다 |
| `site/style.css` | 손으로 쓴 스타일시트 |
| `site/favicon.svg` | 32×32 |
| `site/vercel.json` | 보안 헤더 |
| `site/robots.txt` | 전체 허용 (sitemap 은 도메인 확정 후) |
| `scripts/build-site.mjs` | 생성기 |

**자바스크립트가 한 줄도 없습니다.** 그래서 CSP 를 앱보다 훨씬 좁게 걸 수 있습니다.

## 2. 숫자를 손으로 적지 않습니다

작업 지시서가 짚은 문제가 이것이었습니다 — 기존 소개 문구가 **"5개 언어를 브라우저에서 바로 실행"** 이라고 했는데 Java 와 C 는 실행기에 닿지 않습니다. 별도 사이트에 숫자를 손으로 박아 두면 똑같은 일이 다시 일어납니다. 문제를 하나 추가하는 순간 틀린 숫자가 됩니다.

그래서 `build-site.mjs` 가 `src/data/` 를 esbuild 로 불러 **앱의 실제 데이터에서 직접 세어** 넣습니다.

| 자리표시자 | 출처 |
|---|---|
| `{{TOTAL_PROBLEMS}}` | `problems.length` |
| `{{EXECUTABLE}}` | 실행기가 있는 언어의 `coding` 문제 합 |
| `{{LANG_TABLE}}` | 언어 × 유형 교차 집계 |
| `{{DIFFICULTY_STRIP}}` | 난이도별 개수 |
| `{{DOC_CHAPTERS}}` · `{{DOC_LIST}}` | `docs.ts` 의 챕터 수 / 카테고리별 |
| `{{PY_*}}` · `{{SQL_*}}` | **실제 문제 2개** (`basic_part1_q3`, `sql_q1`) 의 설명·조건·정답·기대 출력 |
| `{{LATEST_*}}` | `changelog.ts` 의 최신 항목 |

`language` 기본값 처리는 `filterProblems` 와 동일하게 맞췄습니다 (`p.language ?? 'python'`). Python 140문제 중 **99개가 `language` 미지정**이라 이걸 틀리면 Python 이 41개로 나옵니다.

예제 문제는 id 로 찾고, **없으면 에러로 중단**합니다. 이름이 바뀐 문제를 설명하는 페이지가 배포되는 것보다 빌드가 실패하는 게 낫습니다.

### 자동 검사

`npm run check:site` 는 재생성해서 기존 파일과 **바이트 비교**합니다. CI 에 들어가 있어서,

- 문제를 추가하고 재생성을 잊으면 → 실패
- `index.html` 을 직접 고치면 → 실패
- 템플릿에 `<script>` 를 넣으면 → 실패 (CSP 가 `script-src 'none'` 이라 브라우저에서 조용히 차단됩니다)
- `"5개 언어를 브라우저에서 바로 실행"` 류 문구가 다시 들어오면 → 실패

## 3. 디자인 — 왜 이렇게 생겼나

랜딩 페이지의 기본값은 보라 그라디언트 히어로, 둥근 카드, 유리 효과, 떠 있는 그림자입니다. 그게 "AI 가 만든 페이지"로 읽히는 조합이고, **이 앱은 이미 반대 방향**입니다.

앱의 시각 언어를 그대로 이어받았습니다.

| | 앱 | 소개 사이트 |
|---|---|---|
| 모서리 | `border-radius: 0` | 동일 |
| 테두리 | 1px `#eaeaea` / 강조는 `#1a1a1a` | 동일 |
| 채움 | 거의 없음 (코드 에디터만 어두움) | 거의 없음 (출력 패널만 어두움) |
| 제목 | Outfit, letter-spacing 음수 | 동일 |
| 수치 | JetBrains Mono | 동일 |
| 그림자 | 모달에만 | 없음 |

구체적으로:

- **구분선으로 레이아웃을 만듭니다.** 카드를 띄우지 않고 1px 격자(`gap: 1px` + 배경색)로 붙입니다
- **"377개" 밑줄**은 형광펜이 아니라 `linear-gradient` 로 만든 0.1em 머리카락 선입니다. 앱에 색 채움이 없어서, 색 블록을 쓰면 다른 제품처럼 보입니다. (inset box-shadow 가 아닌 이유: inline 요소가 줄바꿈되면 line box 마다 따로 그려집니다)
- **출력 패널만 어둡습니다.** 페이지 전체에서 유일하게 채워진 블록이고, 앱의 터미널과 같은 역할이라 일부러 그렇게 뒀습니다
- **"솔직하게 적어 둡니다" 띠**가 유일한 반전 블록입니다. 다크 모드에서 전폭 흰 판이 되지 않도록 `--band-bg`/`--band-ink` 토큰을 따로 뒀습니다

### 다크 모드

`prefers-color-scheme` 으로 토큰을 바꿉니다. **앱의 방식(`filter: invert(1) hue-rotate(180deg)`)을 따르지 않았습니다.** 앱은 인라인 hex 가 수백 군데라 어쩔 수 없이 전체 반전을 쓰지만, 새로 쓰는 코드에 그 꼼수를 물려받을 이유가 없습니다.

### 접근성

- 건너뛰기 링크, `:focus-visible` 윤곽선
- `<h1>` 1개 · `<h2>` 8개 · `<section>` 10개, 계층이 건너뛰지 않음
- 표에 `<caption>`(시각적 숨김)과 `scope` 속성
- `prefers-reduced-motion` 에서 smooth scroll 해제
- FAQ 는 JS 없이 `<details>`/`<summary>`

## 4. 내용에서 의도한 것

**과장하지 않는 게 핵심입니다.** 중·고등학교 수업용이라 교사가 보고 판단할 수 있어야 합니다.

- 히어로 바로 아래 **검은 띠**에 "6개 언어의 문제가 있지만 전부 실행되는 건 아닙니다" 를 먼저 적습니다. 표에서 발견하게 하지 않습니다
- 언어별 표에 Java·C 는 **"코드 실행 없음"** 이라고 그대로 씁니다
- 실제 문제 2개를 **데이터에서 가져와** 보여 줍니다. 스톡 일러스트나 가짜 코드 스크린샷이 아닙니다
- FAQ 에 "왜 Java·C 는 실행이 안 되나요", "가장 어려운 챌린지 문제 일부는 아직 해설이 없습니다" 를 적었습니다 (11번에서 보고한 35개)
- **"학교 컴퓨터실을 전제로 만들었습니다"** 섹션 — 설치 권한 불필요, 로그인 없이 이용, 공용 PC 모드, 60분 자동 로그아웃, 로그아웃 시 흔적 제거. 8번 작업의 결과물이고, 학교 도입 관점에서 실제 차별점입니다

## 5. 배포

**앱과 별개의 Vercel 프로젝트**입니다. 같은 저장소를 쓰지만 Root Directory 를 `site/` 로 지정합니다.

### Vercel 설정 (직접 하실 일)

1. Vercel → Add New → Project → `chani337/pythonexgame` 선택
2. **Root Directory**: `site`
3. **Framework Preset**: `Other`
4. **Build Command**: 비움 (정적 파일이라 빌드 없음)
5. **Output Directory**: 비움 (= `site/` 자체)
6. Deploy

`site/vercel.json` 이 Root Directory 안에 있으므로 헤더가 그대로 적용됩니다.

> `index.html` 은 저장소에 커밋되어 있으므로 Vercel 에서 빌드 단계가 필요 없습니다. 대신 **문제를 추가한 뒤 `npm run build:site` 를 실행하고 커밋**해야 하고, 잊으면 CI 의 `check:site` 가 잡습니다.

### 앱 주소

템플릿의 모든 CTA 는 `{{APP_URL}}` 로, 기본값은 `https://pyquests.vercel.app` 입니다. 커스텀 도메인이 생기면:

```bash
PYQUESTS_APP_URL=https://app.example.com npm run build:site
```

## 6. 아직 안 한 것

- **sitemap.xml** — 절대 URL 이 필요해서 도메인 확정 후(백로그 9번). 바뀔 주소를 지금 등록하면 검색엔진에 잘못된 주소가 들어갑니다
- **OG 이미지 / OG·Twitter 메타** — 9번 작업 범위입니다. 지금 링크를 공유하면 썸네일 없이 뜹니다
- **canonical 링크** — 도메인이 정해져야 의미가 있습니다
- **`/privacy`, `/terms` 링크** — 10번에서 만든 뒤 바닥글에 추가
- **앱 쪽 연결** — 앱에서 소개 사이트로 돌아오는 링크가 없습니다. 도메인 구조(소개 = 루트, 앱 = 서브도메인/경로)가 정해진 뒤 넣는 게 맞습니다
