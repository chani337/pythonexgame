# PWA 업데이트 안내

홈 화면에 추가해서 앱처럼 쓰는 사용자도, 브라우저 탭으로 쓰는 사용자도 **새 버전이 배포되면 알림을 받고, 원할 때 업데이트**합니다. 앱을 지우거나 다시 설치할 필요가 없습니다.

## 1. 전에는 어땠나

PWA 는 이미 적용돼 있었습니다 (React + Vite + `vite-plugin-pwa`, Workbox `generateSW`). 다만 `registerType: 'autoUpdate'` 였습니다.

| | autoUpdate (전) | prompt (후) |
|---|---|---|
| 새 서비스 워커 | 설치되자마자 `skipWaiting` 으로 **즉시** 교체 | 설치 후 **대기** |
| 열려 있는 화면 | 새로고침 **안 됨** — 옛 코드가 새 워커 밑에서 계속 실행 | 사용자가 [업데이트] 를 누를 때까지 그대로 |
| 이전 캐시 | 교체 즉시 삭제 → 옛 화면이 필요한 청크가 사라짐 | 업데이트를 수락한 뒤에만 삭제 |
| 사용자에게 | 아무 안내 없음 | 알림 + [나중에] / [업데이트] |

**전 방식이 "업데이트 직후 흰 화면" 의 근본 원인이었습니다.** `lazyWithReload.ts` 와 `ViewErrorBoundary.tsx` 는 그 증상을 막는 안전망으로 그대로 둡니다.

## 2. 동작

`src/components/UpdatePrompt.tsx` 하나가 전부입니다 (`App.tsx` 맨 아래에 마운트).

### 감지 시점

| 시점 | 방법 |
|---|---|
| 앱 실행 | `registerSW({ immediate: true })` — 브라우저가 등록 시 `sw.js` 를 서버와 비교 |
| 실행 중 | 1시간마다 `registration.update()` |
| 다시 앞으로 올 때 | `visibilitychange` — 마지막 확인 후 5분 넘었을 때만 (홈 화면 앱은 대개 "재실행"이 아니라 "복귀") |
| 인터넷 복구 | `online` 이벤트 |

오프라인이거나 이미 확인 중이면 건너뜁니다. 확인이 실패해도 조용히 넘어가고 다음 시점에 다시 시도합니다.

### 알림과 버튼

- **새 버전 없음** → 아무것도 표시 안 함
- **새 버전 있음** → 상단 알림 `새로운 업데이트가 있습니다.` + [나중에] [업데이트]
- **[업데이트]** → 대기 중인 워커에 `SKIP_WAITING` → 이 창을 제어하면 **정확히 한 번** 새로고침 → 새 버전
  - 대기 중인 워커가 이미 없으면(다른 창에서 적용됨) 그냥 새로고침
  - 15초 안에 제어권이 안 넘어오면 "업데이트를 적용하지 못했어요" — 지금 버전은 계속 사용 가능
- **[나중에]** → 닫힘. `sessionStorage` 에 기록해서 **이 창에서 새로고침해도 다시 묻지 않고**, 앱을 다시 열면 다시 안내

### 여러 창

한 창에서 업데이트하면 다른 창은 **강제로 새로고침하지 않습니다** — 거기에 쓰던 답이 있을 수 있습니다. 대신 `다른 창에서 업데이트를 적용했어요.` + [나중에] [새로고침] 을 띄웁니다.

(`vite-plugin-pwa` 의 기본 동작은 모든 창을 자동 새로고침합니다. `onNeedReload` 로 바꿨습니다.)

### 로그인 · 작성 중인 데이터

- 로그인 세션은 `localStorage` (공용 PC 모드면 `sessionStorage`) 에 있어서 새로고침으로 사라지지 않습니다
- 새로고침은 **사용자가 [업데이트] 를 누를 때만** 일어납니다. 문제 편집기에 쓰던 코드는 저장되지 않으므로, 쓰는 중이면 [나중에] 를 누르면 됩니다 (샌드박스 코드는 원래 `localStorage` 에 저장됨)

## 3. 캐시 정책

| 대상 | 정책 |
|---|---|
| `index.html` | precache (revision 해시) + `NavigationRoute`. 같은 빌드의 JS/CSS 와 항상 짝이 맞음. 새 빌드는 업데이트 수락 후에 |
| `/assets/*.js, *.css` | 파일명에 해시 → 내용이 바뀌면 이름이 바뀜. precache |
| 이전 빌드 precache | `cleanupOutdatedCaches: true` — 새 워커 **활성화 시** 삭제. prompt 모드라 수락 후에만 |
| `sw.js` · `index.html` 서버 헤더 | Vercel 기본 `max-age=0, must-revalidate` (확인함). 업데이트 확인이 HTTP 캐시에 막히지 않음 |
| 없는 `/assets/*` | 404 (vercel.json rewrite 가 `/assets/` 제외) |
| Pyodide · sql.js · 폰트 | runtime cache, 버전이 캐시 이름에 들어 있음 — **변경 없음** |
| Supabase API · 사용자 데이터 | 캐시 안 함 (runtimeCaching 에 없음) — **변경 없음** |

캐시를 통째로 지우는 코드는 없습니다.

## 4. 바꾼 파일

| 파일 | 변경 |
|---|---|
| `vite.config.ts` | `registerType: 'prompt'`, `injectRegister: false`, `cleanupOutdatedCaches: true` 명시 |
| `src/components/UpdatePrompt.tsx` | **신규** — 감지 · 알림 · 적용 |
| `src/App.tsx` | `<UpdatePrompt />` 한 줄 |
| `tsconfig.app.json` | `vite-plugin-pwa/client` 타입 |
| `scripts/verify-shared-pc.mjs` | 새 키 `pyquests_update_dismissed` 의 로그아웃 정책 등록 |
| `scripts/verify-pwa-update.mjs` | **신규** — 아래 테스트 |

`injectRegister: false` 인 이유: 전에는 `registerSW.js` 가 `index.html` 에 자동 삽입됐습니다. `UpdatePrompt` 가 직접 등록하므로 둘 다 있으면 **중복 등록**입니다.

### 자동으로 확인하지 못한 것

- **실제 기기**: iPhone 홈 화면 앱, Android 설치 앱. 헤드리스 Chrome 으로는 OS 의 앱 생명주기를 재현할 수 없습니다
- **로그인 상태 유지**: 테스트 계정이 없어 게스트로만 확인. 세션 저장 위치가 새로고침과 무관한 것은 코드로 확인
- **Safari · Firefox**

## 6. 실제 배포 후 확인할 것

### 이번 배포 한 번은 알림이 안 뜹니다

지금 사용자 기기에 있는 건 **옛 방식(autoUpdate) 페이지**라 알림 화면이 없습니다. 새 서비스 워커는 설치된 뒤 대기하고, **앱(모든 탭)을 완전히 닫았다가 다시 열 때** 적용됩니다. 그 다음 배포부터 알림이 뜹니다.

- iPhone: 앱 전환기에서 PyQuests 를 위로 밀어 종료 → 다시 실행
- Android / PC: 앱 창 · PyQuests 탭을 전부 닫고 다시 열기

### 다음 배포 때 직접 확인 (5분)

1. 휴대폰 홈 화면 앱을 열어 둔 상태에서 배포
2. 앱을 백그라운드로 보냈다가 5분 뒤 다시 열기 → 알림이 뜨는지
3. [나중에] → 그대로 쓸 수 있는지
4. 앱을 완전히 닫고 다시 열기 → 알림이 다시 뜨는지
5. [업데이트] → 한 번 새로고침되고, 로그인이 유지되는지
6. PC 에서 탭 두 개를 열고 한쪽에서 업데이트 → 다른 탭에 "다른 창에서 적용" 안내가 뜨는지

### 브라우저별 차이

- **iOS Safari (홈 화면 앱)**: 서비스 워커 업데이트는 지원. 다만 앱을 백그라운드에 오래 두면 iOS 가 종료시키므로 "복귀" 대신 "재실행" 경로로 감지됩니다. 둘 다 처리합니다
- **서비스 워커를 막은 환경** (일부 사생활 보호 모드 · 학교 정책): 등록이 실패하고 알림 기능만 없습니다. 사이트는 그대로 동작합니다 (코드로 확인 — 실패 시 아무것도 하지 않음. 자동 테스트는 안 함)
